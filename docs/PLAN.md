# 기획서 — 선생님 도구상자

작성일: 2026-07-31

## 1. 한 줄 정의

교사가 반복해서 겪는 잡무를 하나씩 웹 도구로 만들어 모아두고, 링크 하나로 누구나 쓰게 하는 아카이브.

## 2. 왜 만드는가

- 자리 배치, 월말 출결 점검처럼 **매번 똑같이 반복되는데 매번 손이 많이 가는 일**이 있다.
- 이미 개별 도구를 만들어 쓰고 있지만, 바탕화면에 HTML 파일로 흩어져 있어 **나 말고는 쓸 수 없다.**
- 도구가 늘어날수록 "그거 어디 있더라" 문제가 커진다. 모아두는 곳이 먼저 있어야 계속 만들 동력이 생긴다.

## 3. 대상

| 대상 | 필요한 것 |
|---|---|
| 나 (1순위) | 만든 도구를 잃어버리지 않고, 학교 컴퓨터 어디서든 꺼내 쓰기 |
| 같은 학교 동료 교사 | 링크 하나 받아서 설명 없이 바로 쓰기 |
| 검색해서 들어온 다른 교사 | 이 도구가 뭘 해주는지 30초 안에 판단하기 |

**중요:** 3순위 대상은 나에게 질문할 수 없다. 그래서 각 도구는 **설명 없이도 혼자 쓸 수 있어야** 한다.

## 4. 핵심 원칙

1. **자료는 밖으로 나가지 않는다.** 모든 처리는 브라우저 안에서만. 서버로 전송하지 않는다. 학생 이름·출결 기록을 다루는 이상 이건 타협 대상이 아니다.
2. **설치도 가입도 없다.** 링크를 열면 그게 끝이다. 학교 컴퓨터는 설치 권한이 없는 경우가 많다.
3. **도구 하나 = 파일 하나.** 각 도구는 독립된 단일 HTML. 서로 의존하지 않아 하나가 깨져도 나머지는 멀쩡하다.
4. **아카이브는 얇게.** 첫 화면은 목록·검색·설명만 한다. 기능은 도구 안에 있다.
5. **미완성이어도 올린다.** 베타 표시를 달고 올린 뒤 고친다. 완벽해질 때까지 기다리면 아무것도 안 올라간다.

## 5. 무엇을 하지 않는가

의도적으로 뺀 것들이다. 나중에 아쉬워도 다시 검토해서 넣는다.

- ❌ **로그인·회원가입** — 개인정보를 받는 순간 관리 책임이 생긴다.
- ❌ **서버·데이터베이스** — 비용, 유지보수, 개인정보 위험이 한꺼번에 늘어난다.
- ❌ **학생 데이터를 사이트에 저장** — 필요한 설정만 그 사람 브라우저(localStorage)에 남긴다.
- ❌ **프레임워크·빌드 도구** — 순수 HTML/CSS/JS. 1년 뒤에 열어도 그대로 돌아가야 한다.
- ❌ **나이스 자동 연동** — 로그인 정보를 다루게 되고 규정 문제도 생긴다. 파일 내려받아 올리는 방식을 유지한다.

## 6. 구조

```
index.html  ─┬─ data/tools.js  (도구 목록 = 단일 진실 원천)
             ├─ assets/style.css
             └─ assets/app.js

tools/<slug>/index.html   (도구 하나 = 독립 파일. 아카이브와 코드 공유 안 함)
```

도구를 늘리는 비용이 `tools.js`에 항목 하나 추가하는 수준이어야 한다. 그래야 계속 늘어난다.

## 9. 걸림돌과 대비

| 걸림돌 | 대비 |
|---|---|
| 학생 개인정보 유출 걱정 | 오프라인 동작을 사이트·도구 양쪽에 명시. 실제로도 네트워크 요청 없음 |
| 나이스 양식이 바뀌어 출결 점검기가 깨짐 | 도구별 `version`·`updated` 표시. 깨지면 즉시 `status: 'beta'`로 낮추고 안내 |
| 만들어놓고 방치 | 도구 추가 비용을 낮게 유지. 아이디어는 [IDEAS.md](IDEAS.md)에 계속 적어둠 |
| 다른 교사가 잘못 써서 업무 사고 | 각 도구에 "최종 확인은 선생님이" 문구. 도구는 검토를 돕지 결재하지 않는다 |
| 공용 컴퓨터에 학생 명단이 남음 | 도구에 "전체 초기화" 버튼 필수. 안내 문구 포함 |
